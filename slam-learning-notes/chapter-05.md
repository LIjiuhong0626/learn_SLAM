# 第 5 章学习问答笔记

## 2026-10-15—2026-10-30｜project-opencv4-01｜主题：全仓库迁移到 OpenCV 4

- 所属章节与情境：涉及第 5—8、11—13 章；本章重点是图像基础、双目和 RGB-D 示例的构建。
- 提问与回答链：
  1. 用户要求删除 OpenCV 3、只保留 OpenCV 4，并同步修改教学代码、添加注释但不改变源码逻辑。审计确认系统已有 OpenCV 4.5.4，另有用户级 OpenCV 3.4.20；仓库多章仍要求 OpenCV 3，并使用旧头文件路径和全局常量。回答据此把相关 CMake 最低版本统一为 4，并把旧 API 映射到 OpenCV 4 命名空间枚举，保留参数与控制流。
  2. 用户随后在 `ch5/imageBasics/build` 独立执行 `cb`，遇到 `opencv2/*.hpp` 不存在。检查生成的编译标志后确认包含路径为空：子目录独立配置不会继承 `ch5/CMakeLists.txt` 的 `find_package` 结果。回答为三个示例子目录补齐独立的 OpenCV 查找和包含目录。
- 理解变化：已从“源码头文件可能有问题”定位到“独立 CMake 配置没有传入 OpenCV include path”；用户是否能独立复述这一 CMake 作用域规律尚未验证。
- 最终结论：旧全局常量迁移到 `cv::` 枚举不会改变教学算法；需要支持独立构建的子目录必须自行查找依赖。第 5、8、12 章相关目标及第 7 章 OpenCV-only 目标已构建通过，其余章配置阶段已找到 OpenCV 4.5.4。
- 待验证或后续练习：后续可让用户根据 `flags.make` 或 verbose 编译命令独立判断第三方头文件缺失究竟来自代码、安装还是 CMake include path。
